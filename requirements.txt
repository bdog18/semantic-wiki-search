# This drifted badly once before: the pins had aged into
# sentence-transformers 4.0.2 while train.py had moved to the 5.x
# `sentence_transformers.sentence_transformer.*` import paths, so installing
# from this file broke `swsearch train-transfer` at import. Regenerate with
# `pip freeze` rather than editing individual lines.
#
# TensorFlow/Keras (only needed for the archived research encoder in
# research/custom_encoder.py) live in requirements-research.txt instead.
#
# --- torch is deliberately unpinned ---
# It is a direct dependency (mining/triplets.py, train.py) as well as a
# transitive one (via sentence-transformers). The venv here runs
# 2.13.0+cu126 -- a local CUDA build with a version tag PyPI cannot resolve,
# so pinning it would make this file uninstallable anywhere else. `pip
# install torch` from the default index gives the CPU-only build even on a
# machine with an NVIDIA GPU; swsearch.config auto-detects
# torch.cuda.is_available() and only reports "cuda" if a CUDA-enabled build
# is actually installed. For GPU, check `nvidia-smi` for the supported CUDA
# version, find the newest matching tag at https://download.pytorch.org/whl/
# (cu126 matched an RTX 3070 Ti here), then:
#   pip install --index-url https://download.pytorch.org/whl/cu126 torch
# Do NOT add --no-deps -- torch's CUDA build depends on separate
# nvidia-*-cu12 packages that provide the actual .so libraries; skipping them
# breaks `import torch` entirely, not just GPU detection. Those packages are
# omitted below for the same reason: they are torch's to resolve, not this
# file's to pin.
